# 状态与数据

- 区分组件临时状态、URL 状态、跨页面客户端状态和服务端缓存。优先使用已有约定，不因两个组件共享数据就引入新的全局库。
- 列表的筛选/排序/分页进入稳定的 query key；修改筛选后是否重置分页需明确。返回旧请求时不得覆盖新搜索，可取消请求或校验请求序号。
- 表单区分未修改、编辑中、提交中、成功、失败。校验在前端提升体验，服务端仍须校验。失败保留输入，成功刷新相关缓存。
- optimistic update 需要回滚、冲突处理和重复点击策略；不能为视觉顺滑吞掉服务器失败。
- 日期明确时区和格式；金额用项目统一精度方案；大整数 ID 不随意转 Number。可空、零值、空字符串分开处理。
- 上传考虑类型/大小、进度、取消和失败恢复；下载考虑文件名与错误响应，不能把错误 JSON 保存成表格。
- 本地存储需有 schema/版本和失效策略。敏感数据不因方便进入 localStorage；离线/PWA 缓存要有更新与退出清除策略。

## 边界验收

正常、空、失败、权限不足、重复提交、快速连续查询、切页后返回、组件销毁后的响应。只选择与当前改动相关的场景，不机械穷举所有组合。
