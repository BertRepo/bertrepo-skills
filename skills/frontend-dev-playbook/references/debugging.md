# 调试工作流

1. 保存错误原文、复现步骤和运行环境；先读相关代码与最近 diff。不要只凭异常最后一句判断根因。
2. 区分构建/网络/认证/数据/状态/渲染/平台问题。选一个有证据的假设，写清验证信号。
3. 以最低成本验证：检查类型或配置、单个函数测试、请求层日志、授权 HTTP 请求；需要 DOM/交互/水合证据才使用浏览器。
4. 修复根因，保持范围小；不要吞异常、删除校验或盲目清缓存“碰运气”。连续两次假设失败时重新收集证据，停止盲改。
5. 对真实根因选择回归检查。若无可运行环境，交付可复现步骤与具体未验证项。

## 常见分流

- 401/403：身份、token 范围、cookie/CSRF、环境对应关系。
- 404：路由/base path/服务地址/API 版本，而非先归因权限。
- 服务暂时不可用：保留服务端错误、请求 ID/时间、参数来源；可能是依赖故障或输入，不把兜底文案当具体原因。
- 列表错乱：请求竞态、稳定 key、缓存失效、分页参数。
- 样式异常：作用域、级联顺序、父容器尺寸、主题和浏览器支持。
- 内存/卡顿：观察监听器、订阅、计时器、长任务与重渲染；无剖析数据不声称找到性能根因。

线上排查不输出用户敏感数据、不修改生产配置试错。报告：证据 → 根因/剩余假设 → 改动 → 验证。
