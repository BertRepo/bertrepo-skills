# 接口与联调

## 契约先行

定位项目真实 API 层、鉴权策略、base URL 和开发代理。使用 OpenAPI/GraphQL schema、服务端实现或团队文档确认方法、路径、参数、可空字段、分页、错误结构和权限。客户端猜测不是接口事实。

## 可选工具

有 Swagger/Knife4j 工具时先看 schema，再传文档地址/分组/tag/operationId。不假定每个人装有 `swagger__fetch`，也不默认使用上一项目服务地址。跨项目必须确认环境。没工具则读取仓库契约或授权 HTTP 文档，不需要先安装一套 MCP。

## 实现

- 使用现有请求封装、生成客户端或查询库。无封装的小工程可直接 fetch，仍处理状态码、异常和取消。
- 类型与运行时数据不同；在外部数据边界做必要校验。不要用类型断言掩盖错误结构。
- 查询可考虑去重/缓存；写操作不要自动重试到重复提交。时间、金额、大整数、上传格式、流/SSE/WebSocket 要依契约处理。
- token 由项目认证机制管理，不硬编码、不写日志。不把更宽松 CORS 当认证修复。

## Mock 与真实联调

优先用工程现有 mock/MSW/fixture。可用 swagger Mock 工具时记录 taskId、端口、路由范围、启动与停止方式。响应包装、成功码、错误/空/延迟都要与真实契约核对；schema 生成不代表业务行为正确。

临时 Mock 代理替换只用于本地开发，记录原目标并在任务结束时恢复。用户要求的持久开发代理、正式 Mock 基建或授权的生产反向代理修复应保留并交付，不因清理撤回。不要把临时 Mock 地址提交为生产目标。API 问题优先通过请求层日志、授权 HTTP 请求或契约检查定位，真实写接口需有测试数据和执行授权。

## 收尾

只清理本任务的 mock 和缓存文档。未完成联调则交接地址、taskId、剩余问题，不能清空其他会话的任务。报告 mock 验证与真实接口验证的区别。
