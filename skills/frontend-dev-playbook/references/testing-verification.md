# 分层验证

## 按风险选最小充分集合

| 变更 | 推荐验证 |
| --- | --- |
| 文案、低影响样式 | 检查差异；需要时一张目标视口截图 |
| 工具函数、状态转换、复杂条件 | 项目现有单元测试；覆盖边界和异常 |
| 表单、组件交互 | 组件测试或一次目标浏览器交互 |
| 登录、路由、支付等关键跨模块流程 | 项目已有集成/E2E；隔离账号与测试数据 |
| 设计还原、响应式、水合问题 | 目标视口真实渲染检查；静态检查不能替代 |

遵循项目测试契约。有测试基建则复用，没有不要默认安装全套依赖。用户要求 test-first 时先写可失败的行为测试，再实现。断言用户可见行为，不镜像实现；Mock 契约依照真实 API。

## 浏览器预算

开始前确认目标页面、服务是否已有、要回答的问题。不要重复起同一个服务。初始约 8 次操作/1–2 张截图，稳定定位元素；针对长连接页面不要盲等 networkidle。

只扩展能消除真实不确定性的步骤。卡在登录、不可达环境或重复失败时报告具体阻碍，不进行无目标重试。不因预算耗尽就把未验证的关键行为标为通过。

## 产物与结果

运行关联 lint/类型检查/测试/构建；不反复执行已通过且没有新变更的全套检查。区分代码检查、Mock、真实接口、浏览器验收。记录实际命令与结果、已有失败和缺失环境。

临时服务、录屏和测试数据由本任务创建则负责停止或明确交接；不删除其他开发者数据。
