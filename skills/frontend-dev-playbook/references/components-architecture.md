# 组件与应用架构

1. 从页面职责、交互状态和数据流切分组件，遵循项目命名方式。不要为一段仅用一次的简单展示提前创建组件框架。
2. 输入输出显式：props/事件或函数参数描述契约，派生值由源数据计算，不维护两份可冲突状态。
3. 复用现有路由、布局、错误边界和权限入口；路由隐藏不等于服务端授权。
4. Vue/React/Angular/Svelte/原生 Web 的生命周期不同：按实际框架约定处理副作用、取消订阅、计时器和异步清理，不照搬另一框架的 hook。
5. SSR/SSG 先确认代码运行在服务端还是客户端。避免模块级用户状态串请求；渲染期不依赖 window、随机数和不一致的本地时间。浏览器专属模块按需隔离。
6. 跨端项目检查组件能力、平台 API、生命周期及样式限制；没有设备验证时不声称真机通过。

## 常见交付

- 列表：查询、分页/排序、行级操作和状态展示分工清晰，保留用户筛选上下文。
- 表单：展示、校验、持久化分离；修改初始值、取消和提交失败行为明确。
- 组件库：确认公共 API、tokens、键盘行为、版本兼容和示例。破坏性 API 变更要有迁移说明。
- 上传/下载/富文本/图表：优先用已有适配层，考虑大文件、取消、重试、容器 resize 和资源释放。

验证至少覆盖实际变更涉及的交互/状态。无需把小改动升级为整站重构。
