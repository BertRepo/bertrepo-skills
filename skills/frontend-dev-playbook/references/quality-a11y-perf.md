# 无障碍与性能

## 无障碍

优先语义化 HTML。链接负责导航、按钮负责动作；图标按钮有可访问名称，表单 label 与控件关联，错误与提示能被读屏定位。

键盘路径覆盖目标功能：Tab 顺序、可见焦点、弹窗焦点进入/恢复、Escape 关闭约定、菜单键盘行为。组件库已有行为不要覆盖破坏。不要用 aria 隐藏真实交互内容。

按项目目标核查对比度、缩放、触控面积、减少动画和动态状态通知。自动扫描不能代替键盘/读屏验证；未实测时写清楚。

## 性能

1. 先有基线和可复现条件：构建模式、视口、网络、数据规模。定位网络、JS、渲染、布局还是资源瓶颈。
2. 从证据选修复：路由分包、图片尺寸/格式、关键资源、查询去重、缓存、虚拟列表、过量渲染、长任务或资源泄漏。
3. memo/缓存/虚拟化各有成本；不要无差别加缓存或懒加载首屏关键内容。
4. 关注 LCP、INP、CLS 等相关指标，明确实验室与真实用户监测区别；不声称一次 Lighthouse 分数代表线上体验。
5. 在同条件复测实际变更，有数字才报告提升百分比。

遇到任务不涉及的性能问题，记录建议即可，不顺手重写整个页面。
