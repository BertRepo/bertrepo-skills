# 迁移与重构

先定义保持不变的外部行为和必须改变的契约，列出调用方、公共 API、路由、存储格式及部署约束。以既有测试/代表性用例建立基线。

## 分批实施

- 依赖升级：核对版本跨度、官方迁移说明、peer dependencies、运行时与插件兼容。保留 lockfile 语义，不把安装器切换混入升级。
- JS→TS/组件抽取：优先模块边界和真实类型，别用 any/断言暂时遮住所有问题。
- 框架/状态管理迁移：按路由或模块切换，必要时使用兼容适配层，明确其撤除条件。
- 旧页面接手：先确认业务现状，修复目标不等于推倒重做。每批差异可评审、验证和回退。

## 验证与退出

比较关键用户行为、公共 API、持久化兼容、样式和性能。新旧版本并行时检查缓存/事件重复、状态不同步和双请求。

交接已迁移范围、剩余范围、临时适配、兼容边界和回滚步骤。不要将“编译通过”写成“迁移无行为变化”。
