# 项目探查与方案

## 先确认事实

- 读项目指令、README、相关目录及 package.json；monorepo 还要定位目标工作区。
- 以 lockfile 和 CI 为准确认包管理器、Node/运行时版本、脚本。多 lockfile 时找项目约定，不直接重生成。
- 找框架版本、组件库、路由、状态、请求层、测试栈、样式方案和部署目标。不要输出 .env 或登录凭据内容。
- 无 package.json 的静态站点、模板工程或跨端工程同样有效，按实际构建入口处理。

## 已有项目

先看一个相邻页面/组件和一个相关测试，延续约定。提出最小改动位置和验收方式，不因新任务换框架、引入全局状态或新 UI 库。

## 新项目

根据交付目标选择 CSR/SSR/SSG、静态 HTML、路由和数据来源。仅在会改变方案时确认浏览器范围、SEO、登录/权限、国际化、移动端和离线需求。

提供一个有依据的默认方案，不列长篇无关技术选型。依赖安装和外部服务接入按任务授权执行。

## 输出检查点

能回答：改哪里、怎么启动、数据从哪来、如何验证、有无必须确认的缺口。不要把本地路径和个人后端地址写入通用技能配置。
