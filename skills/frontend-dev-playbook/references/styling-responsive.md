# 样式、响应式与国际化

1. 复用项目 tokens/主题和组件库。确认 CSS modules、scoped、CSS-in-JS 或原子类约定，避免新旧体系混杂。
2. 先理解布局约束，再改宽高。优先 flex/grid、合理 min/max、内容驱动；长文本、表格溢出、弹层滚动、sticky 和 z-index 要单独验证。
3. 断点来自产品和现有工程，不只照一张桌面图。选择代表性宽度验证布局，不要求遍历所有设备。
4. 移动端检查触控、键盘顶起、安全区、横屏和滚动锁；跨端样式能力依平台核对。
5. 深色/高对比/减少动画随用户偏好和项目机制；动画不得阻塞操作，尊重 prefers-reduced-motion。
6. 国际化使用现有消息资源，不拼接需要翻译的半句话。考虑文案膨胀、RTL、日期/数字 locale、时区和字体回退。没有多语言需求时不要新增 i18n 框架。
7. 使用项目图标和合法素材，保持图片比例、合理尺寸与占位，避免用大图缩小替代适配资源。

验收比较要固定视口、字体、内容状态和缩放。记录无法从截图确认的字体/间距，不用猜测伪装像素级准确。
