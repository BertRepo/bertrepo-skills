# 构建、部署与观测

- 先查真实部署方式：静态 CDN、Node SSR、容器、平台托管、子路径或跨端发布。读取现有 CI/脚本，不默认改成另一种方案。
- 本地构建失败与部署后白屏分开查。检查运行时/包管理器版本、依赖安装、环境变量作用时机和目标平台差异。
- SPA 刷新 404 检查路由 fallback/base path；资源 404 检查 public path、发布目录、CDN 前缀。SSR hydration 问题检查服务端/客户端内容一致性。
- 客户端环境变量会进入浏览器包。区分 build-time/runtime，不能把密钥“修到”公开变量中。
- 缓存更新检查 hashed assets、HTML 缓存、Service Worker、回滚版本一致性；不要无依据要求用户清空所有缓存或关闭安全策略。
- 跨域/代理检查请求实际目的地、cookie SameSite/Secure、允许来源及后端 CORS，不用 wildcard 掩盖凭据问题。
- sourcemap、错误监控、请求关联 ID 和 source release 依项目隐私策略；错误日志不含 token 或完整个人数据。

## 交付

在用户授权范围内完成构建和可审阅改动。发布前说明目标环境、版本、配置依赖、验收与回滚方式。没有部署授权时停在具体可发布产物，不替用户上线。

只有部署到真实目标且验收后才能报告上线成功。预览链接、构建成功和生产成功是三个不同状态。
